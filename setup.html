Setup guide

How to deploy this demo prototype to your GitHub repository and connect the Supabase project. You do the push yourself — this guide gives you the exact commands.

Read first: UBS-PROFPORT is a UI/UX prototype. It is not a bank, holds no money, issues no real cards, and has no fee-gating of any kind. Keep the demo banner visible on every page.

1. What's in the project 2. Run it locally 3. Supabase setup 4. Add the keys 5. Push to GitHub 6. Deploy

1. What's in the project

ubs-profport/
├── index.html ← marketing / landing page
├── app.html ← customer dashboard (login gate)
├── admin.html ← admin console (separate route)
├── setup.html ← this guide
├── supabase-schema.sql ← schema + seed for Supabase
├── supabase-auth-rls.sql ← auth link + Row Level Security
├── assets/
│ ├── app.css ← design system (light + dark)
│ ├── config.js ← Supabase URL + anon key
│ ├── data.js ← Supabase REST + Auth layer
│ ├── bridge.js ← wires the store to Supabase
│ └── core.js ← i18n (8 langs), FX, UI helpers
└── images/
    └── hero.jpg ← hero visual

Everything is static HTML/CSS/JS — no build step, no framework, no bundler. Data and sign-in go straight to Supabase from the browser using the public anon key.

2. Run it locally

Any static server works. From the project folder:

# Python (built in on most machines)
python3 -m http.server 8080

# or Node
npx serve .

Then open http://localhost:8080. Sign in with a demo account (password demo1234):

  • Customer: alex.morgan@example.com
  • Admin: admin@example.com

The admin console is at /admin.html — a completely separate route from the customer app.

3. Supabase setup

Your project: https://zincdoarinlonbpxiipt.supabase.co

  1. Open the Supabase dashboard for that project.
  2. Go to SQL Editor → New query.
  3. Paste the entire contents of supabase-schema.sql and click Run.
  4. Confirm the tables appear under Table Editor: profiles, accounts, cards, transactions, loans, requests, support_messages, fx_rates.

The script is idempotent — it drops and recreates the demo tables, so you can re-run it safely while iterating.

4. Add the Supabase keys

In Supabase go to Project Settings → API. You need two values:

  • Project URL — https://zincdoarinlonbpxiipt.supabase.co
  • anon public key — safe to expose in a browser app

Create a file called assets/config.js next to core.js:

// assets/config.js  — safe to commit (anon key is public by design)
window.UBS_CONFIG = {
  SUPABASE_URL: "https://zincdoarinlonbpxiipt.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_ANON_PUBLIC_KEY"
};

Then load it in each HTML page, just before core.js:

<script src="assets/config.js"></script>
<script src="assets/data.js"></script>
<script src="assets/core.js?v=4"></script>
<script src="assets/bridge.js?v=1"></script>

Never put the service_role key in the browser. It bypasses Row Level Security. Keep it server-side only (an Edge Function or your own backend).

Live data + real auth (already wired)

The app reads and writes the Supabase tables through assets/data.js (plain fetch against the REST and Auth APIs — no SDK needed). Sign-in uses real Supabase Auth, and the admin console only opens for a profile whose role is admin.

After running supabase-schema.sql, also run supabase-auth-rls.sql. It adds the is_admin() / my_profile_id() helpers, replaces the wide-open demo read policies with per-user Row Level Security, and links the seed profiles to the demo auth users.

Demo accounts (password demo1234 for all):

5. Push to GitHub

Repository: https://github.com/Ubnlord/UBS-PROFPORT

From the folder that contains the project files:

git init
git add .
git commit -m "UBS-PROFPORT demo banking prototype"

# point at your repo (HTTPS)
git branch -M main
git remote add origin https://github.com/Ubnlord/UBS-PROFPORT.git
git push -u origin main

If the remote already exists, use git remote set-url origin … instead of add. If the repo was created with a README, pull first:

git pull --rebase origin main
git push -u origin main

Suggested .gitignore

node_modules/
.DS_Store
.env
.env.local
*.log

Do not ignore assets/config.js — the anon key is meant to be public. Do ignore any .env that holds the service role key.

6. Deploy

Because it is fully static, any of these work with no configuration:

  • GitHub Pages — Settings → Pages → Source: main / root. Site goes live at https://ubnlord.github.io/UBS-PROFPORT/.
  • Netlify / Vercel / Cloudflare Pages — connect the repo, leave the build command empty, publish directory /.

After deploying, open /index.html, /app.html and /admin.html and confirm the demo banner shows on all three.
